## 一、设计意图复盘

spec-02 接续 spec-01，完成 q5 体检的第二步——**逐年拆解**。spec-01 算出“整体看起来还行”，spec-02 立即把“还行”拆成 5 年成绩单。这种节奏设计有意识地模拟“逐步揭穿”的叙事：学员看完整体表会安心，看完逐年表会警觉。【动机】

**为什么 TopNRanking 单独深挖**：要求 6 用 6 个不同动量窗口去复算 TopNRanking，目的是**证伪“只是参数选错了”**这个最便宜的解释。如果换一遍窗口都亏，才更有资格说“这是动量策略的结构性弱点”。这条推理链现在依然是本 spec 最有教学价值的设计点之一。【动机】【验证】

**为什么仍然复用 notebook 当前状态**：q5 章本来就是一条接续型 spec 链，spec-02 站在 spec-01 已生成的 `results`、`eq_bh_portfolio`、`run_strategy` 之上继续推进。当前版本把这些前置依赖写显式了，因此“接续型”不再只是默认心照不宣，而是变成了可检查的状态契约。【结构：接续型】

**当前版本的关键修补**有三处：一是前提检查写明白了；二是最小样本过滤（<20 交易日跳过）写明白了；三是 TopN 深挖明确要求每个窗口只回测一次并复用 `deep_dive`。这三处一起把旧版最容易翻车的点压下去了。

## 四、可改进点

### 改进 1：把年度结果沉淀为 `annual_df`【输出契约】

**现状**：spec 已经清楚定义了列结构，但还没有强制要求结构化 DataFrame 变量。

**改写**：
```markdown
4. 打印逐年对比表：
   - 先构造 `annual_df`
   - index 为年份
   - columns 为四个策略 + 基准
   - print 只是展示层，`annual_df` 供后续 spec 复用
```

**为什么**：这会让 spec-03 甚至 insight 文档的复核都更轻松，不必再从 print 文本里反向解析。

### 改进 2：把年度累乘一致性检查从“建议”升级为“硬要求”【验证】

**现状**：当前 spec 已经把这条校验写进验证段，但还是建议语气。

**改写**：
```markdown
- 对每个策略执行年度累乘一致性断言；
  若误差超过 `0.03`，直接视为本节失败
```

**为什么**：这是本节最有价值的内部一致性检查，值得从“最好做”升级为“必须做”。

### 改进 3：增加一个统一的前提检查代码块【可复现】

**现状**：前提检查是文字要求，没有给出可以直接复制的检查代码。

**改写**：
```python
required = ["run_strategy", "results", "eq_bh_portfolio", "TNR_PORTFOLIO", "RESULT_COLORS"]
missing = [name for name in required if name not in globals()]
assert not missing, f"缺少前置变量: {missing}"
```

**为什么**：接续型 spec 最怕“读懂了文字，但忘了先跑上一节”。给一段统一自检代码，成功率会更高。

## 五、可沉淀的方法点

### A. 这份 spec 已经示范的原则

- **【动机】证伪式深挖**：不是直接下结论，而是先排除“参数选错了”这个最廉价解释。
- **【教学场景：渐进难度】克制单点深挖**：只挖 TopNRanking，不把注意力摊薄。
- **【结构】接续型 spec 链的前置依赖显式化**：这是这轮修补后最值得复用的模板经验。
- **【正向】动态描述方向，避免硬写结论**：继续保持了 q5 章一贯的防幻觉规约。

### B. 当前版本最值得继续沉淀的原则

- **【验证】“每个窗口只回测一次”应视为扫描类 spec 的硬规则**。
- **【同步】颜色、变量名、键名这些“看似小事”其实决定跨节连贯性**。
- **【接续型】前提检查一旦写显式，接续型 spec 的稳定性会明显上升**。

### C. 领域/教学场景特殊考量

- **【教学场景】逐年拆解是金融回测里最基础、也最反直觉的一步**：它把“平均值幻觉”拆开了。
- **【教学场景】最小样本过滤是数据卫生的一部分**：这类边界约束必须写进 spec，不能依赖 AI 自己悟到。
- **【教学场景】“换遍参数都亏”这种排除法，对零基础学员非常有说服力**。
