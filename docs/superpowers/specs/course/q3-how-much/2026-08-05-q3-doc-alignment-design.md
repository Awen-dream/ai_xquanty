# Q3 文档校准设计

## 背景

`docs/superpowers/specs/course/q3-how-much/` 当前已经有一套完整的课程产物：

- 三份主 spec：
  - `spec-01-equal-weight.md`
  - `spec-02-risk-parity.md`
  - `spec-03-momentum-ranking.md`
- 三份对应的评审与复盘文档：
  - `insight-spec-01.md`
  - `insight-spec-02.md`
  - `insight-spec-03.md`
- 一份已经成形的 notebook：
  - `notebooks/q3-how-much.ipynb`

这轮工作的目标不是重做 Q3，也不是重构 notebook，而是把 **spec、insight、notebook 现状** 校准到统一口径，消除已经被修复的问题继续出现在 insight 中、以及 spec 还在要求 notebook 并未采用的实现方式这两类漂移。

## 目标

交付一套可以继续作为课程模板和评审样板使用的 Q3 文档，满足以下目标：

- 三份主 spec 与当前 notebook 实现保持一致；
- 三份 insight 基于当前仓库现状做判断，不再批评已经修复的问题；
- 明确记录这轮仍然存在的真实问题，特别是同步性、验证契约和教学解释不足；
- 不扩大到 notebook 重构，不把一次文档校准变成整章实现改造。

## 范围边界

### 范围内

- 修改 `q3-how-much` 下的 6 个文档文件：
  - `spec-01-equal-weight.md`
  - `spec-02-risk-parity.md`
  - `spec-03-momentum-ranking.md`
  - `insight-spec-01.md`
  - `insight-spec-02.md`
  - `insight-spec-03.md`
- 统一主 spec、insight 与 notebook 的事实口径；
- 补齐必要的验证要求、教学解释和跨市场组合场景说明。

### 范围外

- 修改 `notebooks/q3-how-much.ipynb`
- 修改 `q2` 目录下任何文件
- 修改测试、代码或数据目录
- 借这轮工作顺手重构 Q3 notebook 架构

## 方案选择

### 方案 A —— 推荐

只修文档层，把主 spec 与 insight 同步到当前 notebook 现状。

权衡：

- 优点：
  - 直接命中当前问题的来源；
  - 风险低，不会引入新的 notebook 运行差异；
  - 能最快恢复 Q3 文档链路的一致性。
- 缺点：
  - `COMMON` 等教学设计不会在 notebook 中真实落地，只能在 spec 中降级为建议或结构性约束。

### 方案 B

只修三份主 spec，不动 insight。

权衡：

- 优点：
  - 改动少、速度快。
- 缺点：
  - insight 会继续与现状打架；
  - 之后再做评审时会混淆“旧问题”和“现存问题”。

### 方案 C

spec、insight、notebook 三边一起重构。

权衡：

- 优点：
  - 口径最彻底统一。
- 缺点：
  - 明显扩大范围；
  - 会把一次文档校准变成整章实现改造，不符合本轮目标。

### 推荐结论

采用方案 A。

## 主 spec 修订设计

### `spec-01-equal-weight.md`

修订原则：**以当前 notebook 为准，去掉 notebook 并未采用的错误前提，补入 notebook 已经体现但 spec 漏写的关键规则。**

具体调整：

- 保留固定数据窗口与 `DOWNLOAD_END` 的排他边界说明；
- 保留 `refresh_yfinance(symbol, START, DOWNLOAD_END)` 包装；
- 删除“在等权阶段预计算 `vol`”以及“等权信号通过 `signal.required_indicators` 携带 20 日波动率”的要求；
- 把第 7 步改成“加载 `mktdata` 字典，为后续章节复用”；
- 在画图前显式加入共同交易日对齐要求，解释中美市场交易日不同步会导致净值跳变；
- 在结果呈现或验证段加入权重合法性检查：
  - 权重数量为 3；
  - 权重和为 `1.0 ± 1e-6`；
  - 权重非负。

### `spec-02-risk-parity.md`

修订原则：**保留“差量式教学”的意图，但不再强制 notebook 当前并未落地的写法。**

具体调整：

- 把“使用 spec-01 中已预计算的 `vol` 列”改为“在 `signal_rp.required_indicators` 中按需注册 `vol`”；
- 不再硬性要求“必须提取 `COMMON` 字典”，改成：
  - 建议提取公共配置；
  - 或至少保证等权与风险平价在 `universe`、`signals`、回测参数上结构一致，核心差异集中在 `portfolio` 和指标依赖；
- 保留两张图与指标对比；
- 把验证段从纯描述升级为更可操作的检查项：
  - 风险平价权重不全相等；
  - 权重和为 `1.0 ± 1e-6`；
  - 年化波动率通常不高于等权，若高于则需要解释原因。
- 把分析话术从默认“降低/收窄”改成根据实际数据动态描述方向。

### `spec-03-momentum-ranking.md`

修订原则：**保持当前实现结构不动，但补足教学动机与排序型组合的验证语义。**

具体调整：

- 保留 `Momentum`、`RollingVolatility`、`Ratio` 三指标注册；
- 明确解释：
  - `ram = mom / vol` 的动机是“每承受一份颠簸换回多少涨幅”；
  - 为什么不是直接用 `mom`；
  - `n=3` 在当前 3 只 ETF 池中的教学意义是“全选后再过滤负动量”，而不是强化选股数量本身；
- 不再强行要求复用一个 notebook 中实际不存在的 `COMMON`；
- 强化现金权重语义：
  - 若三只 ETF 均被过滤，剩余权重应明确视为 `CASH = 100%`；
  - 权重和小于 100% 时必须展示现金部分；
- 在验证段补充排序型组合特有的检查：
  - 权重允许为 0；
  - 不允许负权重；
  - 至少能解释出现空白区域的原因。

## Insight 修订设计

### 总体口径

三份 insight 统一增加以下前提：

- 评估基于 2026-08-05 时仓库中的 notebook 现状；
- 主问题从“可复现性”转向“同步性、验证契约与教学解释”；
- 对已经修复的固定日期问题不再继续作为主批评点。

### `insight-spec-01.md`

保留为“修改后可发布”的结论，但更新问题重心：

- 删除把“结束日期为当天”作为核心问题的论据；
- 保留并强化两条仍然成立的问题：
  - spec 对 `vol` 的承诺与 notebook 实际按需注册不一致；
  - spec 未写共同交易日对齐，但 notebook 已实现；
- 把“可复现性”相关评分理由改为“已明显改善”或相应弱化。

### `insight-spec-02.md`

保留 `COMMON` 漂移为主问题，但调整表述：

- 不再单纯批评 notebook“没做到”，而是指出：
  - 若不准备改 notebook，就应把 spec 改成建议而非硬约束；
- 保留“缺少机械 assert”这一真实问题；
- 把“可复现性继承自 spec-01 的当天问题”从主批评点移除。

### `insight-spec-03.md`

保持它是三份中最成熟的一份这一判断，同时把改进重点转向教学动机：

- 保留“动态描述方向”的优点；
- 弱化对同步性的批评；
- 强化对 `ram` 动机与 `n=3` 参数解释不足的指出；
- 保留“排序型组合的验证规则应更明确”这一建议。

## 文件职责

### 主 spec

- 对 AI 或协作者说明“应如何继续生成 notebook 内容”；
- 输出明确的步骤、图表、分析和验证要求；
- 不要求当前 notebook 并不存在的结构。

### Insight

- 记录当前版本的真实强弱项；
- 作为后续课程 spec 的评审模板；
- 不保留已经过时的批评。

## 验证策略

这轮工作的成功标准不是“让 notebook 更强”，而是：

- 6 个文档文件之间没有明显自相矛盾；
- 主 spec 与 notebook 当前实现口径一致；
- insight 不再继续批评已经修复的日期问题；
- 仍然存在的问题被准确记录为：
  - spec / notebook 同步性
  - 权重与现金的验证契约
  - 教学动机解释不足

## 风险与缓解

### 风险 1：为了对齐 notebook，过度削弱 spec 的教学设计

缓解方式：

- 保留设计意图，但把“硬要求”改成“建议做法”或“结构目标”；
- 尤其是 `COMMON`，保留其教学价值，但不伪装成当前已实现事实。

### 风险 2：insight 分数与更新后的文字依据脱节

缓解方式：

- 如果分数仍能支撑，就保留分数、更新理由；
- 如果理由变化明显，就做小幅调整，但避免机械追求“更高分”。

### 风险 3：误把这轮工作扩展成 notebook 实现改造

缓解方式：

- 明确本轮不修改 notebook；
- 若发现 spec 无法在不改 notebook 的前提下对齐，则暂停并重新确认范围。

## 执行顺序

1. 修改三份主 spec；
2. 修改三份 insight；
3. 做一轮自检：
   - 日期口径是否仍有旧说法；
   - 主 spec 是否还在要求 notebook 不存在的结构；
   - insight 是否仍在批评已修复问题；
4. 再进入实际文档改动。

## 审核检查

这份设计默认以下假设成立：

- 本轮工作的目标是文档校准，而不是实现重构；
- notebook 当前实现可作为事实基线；
- `COMMON` 的教学价值可以保留，但不必须在本轮落实到 notebook；
- 用户希望一次性完成主 spec 与 insight 的同步整理。

如果这些假设仍然成立，下一步就是按该设计修改这 6 个文档文件。
